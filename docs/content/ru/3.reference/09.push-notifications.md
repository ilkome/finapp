## Обзор

Финапка доставляет уведомления через **Web Push (VAPID)** существующим service worker'ом PWA - без нативной обёртки, без FCM/APNs. Одна пара VAPID-ключей подписывает каждый push; публичный ключ уходит клиенту, приватный - секрет Supabase-функции.

```
клиент (подписка)             Supabase                       push-сервис
─────────────────             ────────                       ───────────
pushManager.subscribe ──► push_subscriptions (RLS)
                                   ▲
send-push (service role) ──────────┘ читает подписки ──► web-push ──► браузер ──► событие push в SW
```

## Поддержка платформ

- **Android (Chrome)**: работает и в браузере, и в установленной PWA.
- **iOS (Safari 16.4+)**: Web Push работает **только** в PWA, добавленной на домашний экран. Запрос разрешения должен следовать за действием пользователя. Переключатель в настройках показывает подсказку об установке, если приложение открыто в обычной вкладке iOS.

## Составные части

| Часть | Где |
| --- | --- |
| Обработчики SW (`push`, `notificationclick`) | `app/public/sw-push.js`, подключается через `workbox.importScripts` |
| Публичный ключ | `runtimeConfig.public.vapidPublicKey` (`VITE_VAPID_PUBLIC_KEY`) |
| Таблица подписок | миграция `public.push_subscriptions` |
| Жизненный цикл на клиенте | `app/composables/usePushNotifications.ts` + `components/notifications/Settings.vue` |
| Отправитель | `supabase/functions/send-push` |

## Модель данных

`push_subscriptions` живёт **только на сервере** - намеренно исключена из публикации `powersync` и sync-правил, поэтому никогда не попадает в клиентскую SQLite. Клиент пишет и удаляет свои строки через supabase-js (PostgREST) под защитой RLS-политики `push_subscriptions_owner`. Колонка endpoint уникальна, поэтому при повторной подписке клиент делает upsert.

## Функция send-push

`POST /functions/v1/send-push` с телом `{ userId?, title, body?, url?, icon? }`.

Авторизация (шлюз уже требует валидный JWT):

- JWT **service_role** может адресовать любой `userId` из тела (используется cron-задачами и серверными триггерами).
- JWT **пользователя** может адресовать только себя; `userId` из тела игнорируется.

Функция читает подписки целевого пользователя под service role (в обход RLS), отправляет каждую через web-push и удаляет endpoint'ы, которые push-сервис пометил как пропавшие (`404`/`410`).

Секреты: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`.

## Тестовая отправка

```bash
curl -X POST "https://<project>.supabase.co/functions/v1/send-push" \
  -H "Authorization: Bearer <service_role_key>" \
  -H "Content-Type: application/json" \
  -d '{"userId":"<uid>","title":"Finapp","body":"Hello"}'
```

Пользователь должен сначала включить уведомления в Настройках (это сохраняет подписку); иначе вызов вернёт `{ "sent": 0, "note": "no subscriptions" }`.

## Напоминания о платежах

`supabase/functions/payment-reminders` запускается каждый час (`pg_cron`, задача `payment-reminders-hourly`) и отправляет напоминания через `send-push`. Принимает только вызов с service role, потому что читает данные всех пользователей. Отбор - обычный модуль `app/app/components/loans/paymentReminders.ts` поверх правил самого приложения (`minPaymentOf`, `graceOf`, `deriveLoan`, `deriveUpcoming`).

| Вид | Когда | Пропускается, если |
| --- | --- | --- |
| `loan` | за `REMINDER_DAYS_BEFORE` дня до ближайшего платежа по графику займа | платёж уже внесён (считается первая неоплаченная строка) |
| `minPayment` | за `REMINDER_DAYS_BEFORE` дня до даты минимального платежа карты | минимум погашен |
| `grace` | за `REMINDER_DAYS_BEFORE` дня до конца льготного периода | он погашен или долг по выписке равен 0 |
| `graceMissed` | на следующий день после конца льготного периода | он погашен |

- Пользователь обрабатывается в запуске, когда его местное время 10:00 (`user_settings.timezone`, `Europe/Moscow`, если пусто); дни - календарные дни в этой зоне.
- Напоминание, пропущенное запуском, уходит в более позднем, пока срок не прошёл. `graceMissed` отправляется один раз, в день после срока или позже.
- Напоминания одного кошелька на один срок объединяются в один пуш со всеми суммами. Текст на русском при локали `ru`, иначе на английском.
- Пропускаются: пользователи с `user_settings.paymentReminders = false`, архивные кошельки, минимумы и суммы льготного периода, которые не обновлялись дольше `MIN_PAYMENT_STALE_DAYS`.
- Дедупликация: когда `send-push` сообщил хотя бы об одной доставке, ключи (`userId`, `walletId`, `kind`, `dueDate`) записываются в `payment_reminders_sent`. Неудачная отправка, как и отправка без подписанных устройств, повторяется в следующем запуске.
- `POST ...?dryRun=1` возвращает пуши, которые были бы отправлены (пользователь, кошелёк, виды, заголовок, текст), без отправки и записи. Он не проверяет час 10:00 и берёт местный день каждого пользователя, поэтому его можно запускать в любое время.

Секреты: своих нет (используется service role ключ окружения функции); cron-задача читает `project_url` и `service_role_key` из Vault, см. [деплой](/ru/development/deployment).
