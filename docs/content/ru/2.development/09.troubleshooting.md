## Локальный Docker / Supabase

### Colima: отключите аналитику Supabase

На Colima (альтернатива Docker для macOS) контейнер `vector` (аналитика логов) Supabase не стартует, потому что не может примонтировать Docker-сокет. Отключите его в `app/supabase/config.toml`:

```toml [app/supabase/config.toml]
[analytics]
enabled = false
```

Без этого `supabase start` зависает или падает с ошибкой на Colima.

### Образ postgres:18 - неверный путь монтирования тома

Если используете контейнер `postgres:18` (например, для bucket-storage базы PowerSync), монтируйте том с данными в `/var/lib/postgresql`, **а не** в `/var/lib/postgresql/data`:

```yaml
volumes:
  - pg_storage_data:/var/lib/postgresql
```

Монтирование в `/var/lib/postgresql/data` роняет контейнер при старте, потому что postgres:18 изменил каталог данных по умолчанию.

## Клиент PowerSync

### Нет `INSERT ... ON CONFLICT` в таблицах PowerSync

Клиентские таблицы PowerSync - это SQLite-**представления** (views) с триггерами INSTEAD OF. Они принимают обычные `INSERT`, `UPDATE` и `DELETE`, но **не** `INSERT ... ON CONFLICT` (синтаксис upsert).

Upsert нужно делать вручную - сначала проверить наличие строки, затем INSERT или UPDATE:

```ts
// из app/services/powersync/mutations.ts
async function upsertRow(table, id, row) {
  await db.writeTransaction(async (tx) => {
    const existing = await tx.getOptional(`SELECT id FROM ${table} WHERE id = ?`, [id])
    if (existing) {
      await tx.execute(`UPDATE ${table} SET ... WHERE id = ?`, [...values, id])
    }
    else {
      await tx.execute(`INSERT INTO ${table} (id, ...) VALUES (?, ...)`, [id, ...values])
    }
  })
}
```

Полная реализация - в `app/services/powersync/mutations.ts`.

### У каждой синхронизируемой таблицы должен быть PK `id`

PowerSync требует первичный ключ `id` в каждой синхронизируемой таблице. У `user_settings` в колонке `id` лежит uid пользователя Supabase - так таблица удовлетворяет требованию, имея ровно одну строку на пользователя.

## Синхронный auth-гейт

Роут-гард в `app/app/middleware/auth.global.ts` синхронный - он читает персистнутую сессию Supabase из localStorage (`hasPersistedSession()`, `app/app/composables/useAuthSession.ts`) без сетевого запроса, поэтому работает офлайн. Auth-cookie нет.

supabase-js сам персистит сессию в localStorage в процессе входа, так что к моменту навигации из кода логина гейт уже проходит. Плагин PowerSync отдельно следит за реактивным `uid` из `useSupabaseAuth()` и подключает/отключает PowerSync по мере резолва сессии - навигация его не ждёт.

Если переносите логику входа, переходите на другой роут только после резолва промиса входа (сессия персистнута) - иначе гард вернёт на `/login`.
