`app/scripts/backup-finapp.mjs` делает выгрузку данных одного пользователя через PostgREST. Скрипт только читает и ничего не пишет в базу.

Это инструмент администратора сервера: ему нужен service-role ключ проекта, который обходит RLS. Пользователь запустить его для своих данных не может.

## Запуск

Из корня репозитория:

```bash [Terminal]
SB_URL=https://<ref>.supabase.co \
SB_SERVICE_ROLE=<service_role_key> \
SB_EMAIL=user@example.com \
SB_LABEL=prod \
pnpm --dir app run backup
```

| Переменная | Обязательна | Значение |
|------------|-------------|----------|
| `SB_URL` | да | URL проекта Supabase |
| `SB_SERVICE_ROLE` | да | Service-role ключ; он обходит RLS, поэтому не оставляйте его в истории шелла и никогда не коммитьте |
| `SB_EMAIL` | да | Пользователь для бэкапа; скрипт находит его uid по email через auth admin API. Без него скрипт не запускается, поэтому в выгрузку не попадают данные других пользователей |
| `SB_LABEL` | нет | Часть имени файла, по умолчанию `backup` |
| `SB_OUTDIR` | нет | Папка для файла, по умолчанию `~/finapp-backups` |

Секреты берутся только из env, никогда из аргументов.

## Результат

Один файл на запуск: `<SB_OUTDIR>/finapp-<label>-<timestamp>.json`, с блоком `meta` (время, email, label, uid, URL) и массивом строк на каждую таблицу. Папка намеренно вне репозитория: в файле реальные финансовые данные, коммитить его нельзя.

Таблицы:
- все пер-юзерные таблицы из `SYNCED_TABLES` (`app/services/powersync/tables.ts`), отфильтрованные по `userId` пользователя;
- глобальная таблица `rates`, без фильтра.

Каждая таблица читается постранично. Скрипт печатает число строк по каждой таблице; если любой запрос падает, он печатает имя таблицы и HTTP-ошибку и завершается, не записав файл, так что сохранённый бэкап никогда не бывает молча обрезан.

## Восстановление

Скрипта восстановления нет. JSON нужен для просмотра и ручного импорта, например рецептом с `\copy` из [Деплоя](/ru/development/deployment#импорт-существующих-данных-remap-userid).
