`app/scripts/backup-finapp.mjs` makes a read-only dump of one user's data through PostgREST. It writes nothing to the database.

This is a server admin tool: it needs the project's service-role key, which bypasses RLS. Users cannot run it against their own data.

## Running

From the repo root:

```bash [Terminal]
SB_URL=https://<ref>.supabase.co \
SB_SERVICE_ROLE=<service_role_key> \
SB_EMAIL=user@example.com \
SB_LABEL=prod \
pnpm --dir app run backup
```

| Variable | Required | Meaning |
|----------|----------|---------|
| `SB_URL` | yes | Supabase project URL |
| `SB_SERVICE_ROLE` | yes | Service-role key; it bypasses RLS, so keep it out of shell history and never commit it |
| `SB_EMAIL` | yes | The user to back up; the script resolves their uid by email through the auth admin API. Without it the script refuses to run, so a dump never holds other users' data |
| `SB_LABEL` | no | Name part of the output file, `backup` by default |
| `SB_OUTDIR` | no | Output directory, `~/finapp-backups` by default |

Secrets come from env only, never from arguments.

## Output

One file per run: `<SB_OUTDIR>/finapp-<label>-<timestamp>.json`, with a `meta` block (time, email, label, uid, URL) and one array of rows per table. The directory is outside the repo on purpose: the file holds real financial data and must never be committed.

Tables:
- every per-user table in `SYNCED_TABLES` (`app/services/powersync/tables.ts`), filtered to the user's `userId`;
- the global `rates` table, dumped unfiltered.

Each table is read page by page. The script prints a row count per table; if any request fails it prints the table name and the HTTP error and exits without writing the file, so a saved backup is never silently truncated.

## Restoring

There is no restore script. The JSON is for inspection and for a manual re-import, for example with the `\copy` recipe in [Deployment](/en/development/deployment#importing-existing-data-userid-remap).
