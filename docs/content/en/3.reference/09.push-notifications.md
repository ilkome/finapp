## Overview

Finapp delivers notifications via **Web Push (VAPID)** through the existing PWA
service worker - no native wrapper, no FCM/APNs. One VAPID keypair signs every
push; the public key ships to the client, the private key is a Supabase function
secret.

```
client (subscribe)            Supabase                       push service
─────────────────             ────────                       ────────────
pushManager.subscribe ──► push_subscriptions (RLS)
                                   ▲
send-push (service role) ──────────┘ reads subs ──► web-push ──► browser ──► SW push event
```

## Platform support

- **Android (Chrome)**: works in the browser and the installed PWA.
- **iOS (Safari 16.4+)**: Web Push works **only** in a PWA installed to the home
  screen. The permission prompt must follow a user gesture. The settings toggle
  shows an install hint when running in a non-standalone iOS tab.

## Pieces

| Piece | Location |
| --- | --- |
| SW handlers (`push`, `notificationclick`) | `app/public/sw-push.js`, injected via `workbox.importScripts` |
| Public key | `runtimeConfig.public.vapidPublicKey` (`VITE_VAPID_PUBLIC_KEY`) |
| Subscriptions table | `public.push_subscriptions` migration |
| Client lifecycle | `app/composables/usePushNotifications.ts` + `components/notifications/Settings.vue` |
| Sender | `supabase/functions/send-push` |

## Data model

`push_subscriptions` is **server-side only** - deliberately excluded from the
`powersync` publication and sync rules, so it never reaches client SQLite. The
client writes/removes its own rows via supabase-js (PostgREST), guarded by the
`push_subscriptions_owner` RLS policy. The endpoint column is unique so the
client upserts on re-subscribe.

## send-push function

`POST /functions/v1/send-push` with `{ userId?, title, body?, url?, icon? }`.

Authorization (the gateway already requires a valid JWT):

- A **service_role** JWT may target any `userId` in the body (used by cron jobs
  and server-side triggers).
- A **user** JWT may only target itself; the body `userId` is ignored.

The function reads the target user's subscriptions with the service role
(bypasses RLS), sends each via web-push, and prunes endpoints the push service
reports as gone (`404`/`410`).

Secrets: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`.

## Test send

```bash
curl -X POST "https://<project>.supabase.co/functions/v1/send-push" \
  -H "Authorization: Bearer <service_role_key>" \
  -H "Content-Type: application/json" \
  -d '{"userId":"<uid>","title":"Finapp","body":"Hello"}'
```

A user must enable notifications in Settings first (which stores a subscription);
otherwise the call returns `{ "sent": 0, "note": "no subscriptions" }`.

## Payment reminders

`supabase/functions/payment-reminders` runs every hour (`pg_cron`, job `payment-reminders-hourly`) and sends reminders through `send-push`. It accepts a service-role caller only, because it reads every user's data. Selection is the plain module `app/app/components/loans/paymentReminders.ts`, built on the app's own rules (`minPaymentOf`, `graceOf`, `deriveLoan`, `deriveUpcoming`).

| Kind | Sent | Skipped when |
| --- | --- | --- |
| `loan` | `REMINDER_DAYS_BEFORE` days before the next schedule payment of a loan | the payment is paid (the next unpaid row is what counts) |
| `minPayment` | `REMINDER_DAYS_BEFORE` days before the card's minimum payment date | the minimum is paid |
| `grace` | `REMINDER_DAYS_BEFORE` days before the interest-free period ends | it is paid or the statement debt is 0 |
| `graceMissed` | the day after the interest-free period ends | it is paid |

- A user is processed in the run where their local time is 10:00 (`user_settings.timezone`, `Europe/Moscow` when empty); days are civil days in that zone.
- A reminder missed by a run is sent on a later one while the due day is not past. `graceMissed` is sent once, on or after the day after.
- Reminders for one wallet and one due day are merged into one push that lists every amount. The text is Russian when the user's locale is `ru`, English otherwise.
- Skipped: users with `user_settings.paymentReminders = false`, archived wallets, and minimums or interest-free amounts that were not refreshed for `MIN_PAYMENT_STALE_DAYS`.
- Dedupe: after `send-push` reports at least one delivery, the keys (`userId`, `walletId`, `kind`, `dueDate`) are inserted into `payment_reminders_sent`. A failed send, or one with no subscribed device, is retried on the next run.
- `POST ...?dryRun=1` returns the pushes it would send (user, wallet, kinds, title, body) without sending or recording. It ignores the 10:00 gate and uses each user's local day, so it can be run at any time.

Secrets: none of its own (it uses the function environment's service role key); the cron job reads `project_url` and `service_role_key` from Vault, see [deployment](/en/development/deployment).
