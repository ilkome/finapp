## Overview

Every transaction moves money out of a wallet, into a wallet, or both. A row has two sides, each a wallet and an amount set together:

- **from side**: `from_wallet_id` / `from_amount` (`fromWalletId` / `fromAmount` in TypeScript), money leaving a wallet;
- **to side**: `to_wallet_id` / `to_amount` (`toWalletId` / `toAmount`), money entering a wallet.

`type` is a string, the same in the database and in TypeScript (`TrnType` in `app/app/components/trns/types.ts`):

| `type` | from side | to side | `category_id` |
|--------|-----------|---------|---------------|
| `expense` | set | none | required |
| `income` | none | set | required |
| `transfer` | set, or none when the source is outside the app | set, or none when the target is outside the app | none |
| `adjustment` | set when lowering the balance | set when raising it | none |

Amounts are positive integers in the minor units of the side's wallet currency (see [Data Model](/en/reference/data-model)). The two amounts of a transfer differ only when the wallets have different currencies.

## Validation

The `transactions` check constraints and `trnItemSchema` enforce the same rules, so a row the server would reject never enters the upload queue:

- a wallet and its amount are set together, and amounts are `> 0`;
- `expense` has only the from side and a category; `income` has only the to side and a category;
- `adjustment` has exactly one side and no category;
- `transfer` has at least one side, two different wallets when it has both, and no category;
- `date` is a civil day (UTC-midnight ms).

## Expense and Income

Ordinary spending and earning. Both require a wallet, an amount and a category, and both count in income/expense statistics unless the category is excluded from statistics (`is_excluded_from_stats`).

## Transfer

Money moved between wallets. It never counts as income or expense.

- Both sides set: money moves from one wallet to another, possibly in different currencies with two amounts.
- One side set: the other side is **outside the app** (a payment to someone's card, money arriving from an account that is not tracked). The transfer form can mark either side "Outside the app".
- A transfer has no category.

## Adjustment

A balance correction for one wallet. It changes the wallet balance but stays out of income/expense statistics.

- To side set: raises the balance ("found money", correction up).
- From side set: lowers the balance ("lost money", correction down).
- An adjustment has no category and is told apart by `type === 'adjustment'`, never by a category.

## Balances

A wallet balance is the sum of `to_amount` into it minus the sum of `from_amount` out of it, with one rule for every type (`getWalletsTotals` in `app/app/components/amount/getTotal.ts`). A side whose wallet no longer exists is skipped.

## Reserved categories and looks

Transfers and adjustments have no category, but they still have a name, color and icon in lists. `getTrnLook(trn)` in `useCategoriesStore` returns the category of an expense or income, and the type's look for a transfer or adjustment.

Two category ids are reserved and have no `categories` row: the store injects them.

| ID | In statistics | Editable | Where assigned |
|----|---------------|----------|----------------|
| `loan_interest` | yes | name, color, icon, parent | The **Loan interest** field of a transfer into a credit wallet |
| `loan_fine` | yes | name, color, icon, parent | Picked by the user for loan fees and fines |

They are ordinary expenses and count in statistics. They are never deleted.

The looks of `loan_interest`, `loan_fine` and of the `transfer` and `adjustment` types are edited on the same screen and stored in `display_overrides` (kind `category` or `transaction_type`, id `<userId>:<kind>:<targetId>`). `isReservedCategoryId` in `app/app/components/categories/utils.ts` covers all four ids, so `saveCategory()` routes them to the override path.

## Type change

The form writes the whole row on save. When the type changes, the sides and category that do not belong to the new type are written as `null` (`itemToRow` writes every mapped column, absent values as null), so only the fields relevant to the current type carry values locally and on the server.

## Statistics

`getTotal()` returns base-currency minor units, each rounded once:

| Field | Includes |
|-------|----------|
| `income` | `income` rows, except excluded categories |
| `expense` | `expense` rows, except excluded categories |
| `adjustment` | `adjustment` rows: to side plus, from side minus |
| `incomeTransfers` | To sides of transfers |
| `expenseTransfers` | From sides of transfers |
| `net` | `income - expense` |
| `sumTransfers` | `incomeTransfers - expenseTransfers` |
| `missingRates` | Currencies left out for lack of a rate |

Lists, statistics and filters tell transfers and adjustments apart by `type`.
